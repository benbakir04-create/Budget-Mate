# 0003: استخدام Supabase كخادم خلفي وقاعدة بيانات (Backend)

**التاريخ:** إبريل 2026  
**الحالة:** معتمد (Accepted)

## السياق (Context)
المشاريع القديمة (`teacher-report-simple`) كانت تستخدم Google Apps Script و Google Sheets كقاعدة بيانات. مع الانتقال لمشروع متكامل ومستقل بقابلية للتوسع (Scalability) ويدعم PWA والمزامنة، كان لا بد من اختيار خادم خلفي احترافي.

## القرار (Decision)
تم اختيار **Supabase** كـ Backend-as-a-Service (BaaS) لإدارة قواعد البيانات والمصادقة (Authentication).

## المبررات (Rationale)
1. **قوة PostgreSQL:** على عكس Firebase الذي يستخدم NoSQL، يستخدم Supabase قواعد بيانات PostgreSQL العلاقية، وهي الخيار الأنسب على الإطلاق للأنظمة التعليمية (مدارس -> صفوف -> طلاب -> مواد -> درجات) لوجود علاقات قوية بين الجداول.
2. **المصادقة الجاهزة (Built-in Auth):** لا حاجة لبرمجة نظام الدخول وتشفير كلمات المرور من الصفر.
3. **سهولة التكامل:** يتوافق بشكل ممتاز ورسمي مع Next.js App Router (يوجد حزم رسمية للتعامل مع الـ Cookies والـ Server Components).
4. **سياسات الأمان (RLS):** حماية قوية جداً على مستوى الصفوف (Row Level Security)، فالمعلم لا يمكنه رؤية درجات طلاب مدرسة أخرى أبداً.

## العواقب (Consequences)
- يتطلب تعلم التعامل مع سياسات RLS لضمان الأمان بدلاً من الاعتماد التام على الخوادم لحجب البيانات.
- الانتقال (Migration) من Google Sheets للسجلات الجديدة يتطلب كتابة سكربت محدد لجلب الداتا القديمة مرة واحدة (سيتم معالجته لاحقاً).
