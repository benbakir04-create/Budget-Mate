## 2. القرارات السارية

1. **المعمارية:** منهجية «ركيزة»: واجهة ثابتة على GitHub Pages + Supabase، بلا خادم تطبيقات (ADR 0005).
2. **النطاق:** المسار العائلي للجزائر، والعملة الافتراضية الدينار. مسار الأعمال والمستشار الذكي والدفع الإلكتروني مؤجلة.
3. **قرارات علي** (Q-01 إلى Q-06 في الجرد):
   - مشروع Supabase جديد ومستقل، والمجلد خارج OneDrive.
   - الشريك لا يعدّل ولا يحذف، ويدخل بدعوة بريد.
   - الصندوق قد ينزل تحت الصفر مع تنبيه.
   - الصندوق يؤرشف ولا يُحذف.
4. **التصميم:** الاتجاه «مشرق ومرح» الزمردي، الخط Readex Pro، والشريط السفلي فاتح بصحن أخضر.
   - المرجع: لوحتا علي في Pinterest.
   - المعاينة: شاشات كاملة متجاورة وفيديو حركة، لا صور متراكبة.
5. **الدمج:** علي فوّض الدمج بعد CI أخضر. السؤال قبل الدمج يبقى لثلاثة: تطبيق ترحيل على القاعدة الحقيقية، والنشر، وحذف بيانات.

## 5. قواعد العمل (لا تُخالف)

- لا تعديل لقاعدة البيانات إلا بترحيل جديد، بهذا التسلسل:
  1. يُختبر محليًا (`npm run test:db`).
  2. يمر في CI.
  3. يُطبَّق على Supabase.
  4. يُسمّى الملف بالإصدار الذي سجّله Supabase.
  5. تُولَّد الأنواع.
- لا تعديل لترحيل سبق دمجه.
- كل سياسة RLS أو دالة جديدة يرافقها فحص يفشل بدونها.
- المفتاح السري لـ Supabase لا يدخل كود الواجهة ولا المستودع. المتصفح يحمل المفتاح العام فقط.
- فرع لكل عمل، ودمج في `main` بعد CI أخضر.
- مع علي: بالعربية وبلا مصطلحات، وخطوة واحدة في كل رسالة مع روابط مباشرة. لا يُطلب منه لصق أي سر في المحادثة.
- حدّث هذا الملف في نهاية كل جلسة.
