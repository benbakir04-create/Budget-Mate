# الوثيقة المعمارية التقنية (Technical Architecture Document)

**المشروع:** تطبيق وازن (Wazen / Budget Mate)
**الجمهور المستهدف:** المبرمجون المساعدون، فرق التدقيق البرمجي.

---

## 1. الفلسفة المعمارية (Architectural Philosophy)

تم تصميم تطبيق "وازن" ليكون تطبيقاً تشاركياً مالياً خفيفاً يعتمد على مبدأ فصل المسؤوليات (Separation of Concerns). يتكون النظام من مستودعين رئيسيين داخل المشروع:

1. **الواجهة الأمامية (Frontend Shell):** تطبيق React SPA مبني ومحسن بواسطة Vite.
2. **الخلفية (Backend Brain):** خادم Express.js يوفر واجهة RESTful API آمنة للعمليات والمطابقة.

---

## 2. حزمة التقنيات (Tech Stack & Justifications)

### 2.1. الواجهة الأمامية (Frontend)

- **React v18 + Vite:** تم اختيار Vite لضمان سرعة بناء فائقة للإنتاج، وتوليد حزم برمجية (Bundles) صغيرة الحجم وعالية الكفاءة.
- **Tailwind CSS & Vanilla CSS:** لتطبيق الهوية البصرية الفاخرة المعتمدة على تصميم الـ Glassmorphism والتأثيرات الناعمة دون التضحية بحجم الكود.
- **React Router Dom & React-i18next:** لتوجيه المسارات داخل التطبيق ودعم اللغتين (العربية/الإنجليزية) بشكل مرن ورسمي.

### 2.2. الخلفية وقاعدة البيانات (Backend & Database)

- **Node.js + Express:** لبناء خادم سريع وخفيف للتعامل مع الطلبات المالية الفورية وإدارة الجلسات.
- **Prisma ORM:** لتسريع كتابة وتطوير الاستعلامات وحماية البيانات عبر ترحيلات (Migrations) واضحة وآمنة.
- **PostgreSQL / SQLite:** قواعد بيانات علائقية قوية ومثالية للتعامل مع الحركات المالية المشتركة المعقدة.

---

## 3. نموذج الأمان وجدار الخصوصية (Backend Privacy Firewall)

أحد الأعمدة الأساسية في معمارية وازن هو فرض الأمان في جهة الخلفية (Server-Side) وليس فقط إخفاء الواجهات:

1. **جدار الخصوصية للفئات الحساسة (Private Categories):**
   - عند جلب الفئات للمستخدم المساعد (Partner)، يقوم الخادم تلقائياً باستبعاد أي فئة موسومة بـ `isPrivate: true` لمنع تسرب بيانات المالك الخاصة.
2. **أمن التعديل والحذف (Ownership Validation):**
   - لا يمكن تعديل أو حذف أي حركة مالية إلا إذا كان معرف المستخدم يطابق صانع الحركة، أو إذا كان المستخدم هو المالك الرئيسي (Owner) للشريك الذي سجل الحركة.
3. **أمان الـ AI:**
   - محرك الذكاء الاصطناعي لا يقرأ سوى المعاملات المسموح بها، ويتم عزل بيانات المالك الخاصة تماماً عن أي تحليلات تظهر للشريك.

---

## 4. استراتيجية البناء والنشر (Build & Deploy)

- **مجلد الإنتاج (Dist):** يتم توليد حزم جافاسكربت ومستندات CSS محسنة عند تنفيذ `npm run build` في مجلد الواجهة الأمامية.
- **إدارة التكوين (.env):** استخدام ملفات البيئة للتحكم في معطيات التشغيل (عناوين الـ API، عناوين قواعد البيانات، ووضع النسخة التجريبية `VITE_DEMO_MODE`).
